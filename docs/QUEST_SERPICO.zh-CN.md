# 瑟皮科原任务流程

8.1.3 已完成当前原生源流程整理；没有任务改动或新实机声明。依据为当前 `SerpicoStoryline` 和 `StoreClientUniqueList` 的原CIL及嵌套回调，未执行Debug方法或读取存档。

## 日程与投食

令S为原serpico实际锚点，名义40。正常模式下的原节点如下；未启用会压缩间隔的原测试模式。

| 节点 | 正常日期 | 原附加条件 |
|---|---|---|
| Serpico1／3／4／5／6 | S、S+2、S+3、S+5、S+6 | 沿各自工厂与原调度，后段举报检查在这些日期分派之后 |
| 乔治欧送信 | S+8 | 未被原举报条件拦截；信对白开始回调一次性设置已送达并放信 |
| 食物结算N | 送信日+3+原额外天数 | 必须已送信；到N仍未饱食时触发原死亡新闻 |
| 巡检回访 | N+1 | 已送信、未被举报且已饱食 |
| 文件选择 | N+3 | 同上 |
| 文件后果新闻 | N+4 | 选择1出义军新闻；选择3出执法新闻 |
| 人物结局 | N+6 | 原选择为1、2或3，且仍满足前段资格 |

当前出厂代码的 `IsFed()` 门槛为**2000热量**，不是此前构想举例的1200。这里保留当前原值，不用旧描述重写游戏。没有额外天数时，名义日期分别是40／42／43／45／46、48、51、52、54、55、57；这些只是正常日程计算，不是自然到访实测日期。

投食窗口要求：原已送信、未被举报、尚不足2000，并且 `LetterDay ≤ today < LetterDay+FoodNights`。弃物场原离场回调递归查找FOOD且有CALORIE_VALUE_TAG的物品，用每件热量乘 `max(1,unitCount)` 求和。只有正热量才加入原 `serpicoFoodKcal`。因此原任务允许多次有效离场投食累计，不能误写成只判单件或只判食品价格。

原场内每0.5秒的检查只提示“已有累计＋现场食物”是否达到2000，本身不把现场食物写入任务累计。实际累计在原离场方法中发生。尚未达到门槛的一次有效投食，若当日还未加过天数，会额外延长1日；同日再次离场不再加天数。该延期也相应移动后续结算、回访与文件日程。物品在地点退出中的完整清理沿原地点业务，本记录不把计数方法单独当作物品消耗证明。

`IsReported()` 接受原 `serpicoReported` 或 wantedStatus中 `serpico6==1`。举报后送信／投食／后段分派受原拦截，不能靠仍有食物数值认定整条线成功。

## 乔治欧代送的原选项

送信来访另提供代送：150信用点且现金足够时原扣款；或外城原LL声望≥40时求人情。成功回调直接将原投食累计置为2000并记夜报，不另造本MOD任务分。肢体残缺或重伤会影响能否亲自前往的原对白，但不把未支付、拒绝或条件不足写成代送成功。现有选项、条件和原后果保持。

## 文件选择与人物后续

| 原选择值 | 去向与后续 | 原奖励／其他条件 |

| 1 | 文件交义军，次日相应新闻；结局用serpico_rev与原义军归属 | 结局对白开始时原义军声望+12 |

三条正常人物结局保留原免费奖励三选一：`storage_bay_large ×1`、`module_bay_expansion_kit ×4`、`current_converter ×2`。原摆放、奖励实例与领取回调保持，不把三个选项同时发给玩家。

选择1和2的原结局还设置600通缉值、可拘捕与原射击算捕获行为。捕获回调把文件选择改为4，并按原路径扣对应义军／黑市声望27；原执法处置对白继续运行。选择3不使用这组结局通缉设置。不能因已经看见感谢或奖励选项，就宣布人物从此不再受玩家处置影响。

本MOD只沿现有NPC、称呼、物品与界面显示映射呈现这些原内容；条件、数值、日期、奖励、原选择和人物命运不改。没有把待定刺客的“每次窗口离开／66%”规则接入本任务，也不为本源流程记录重跑已通过通路。
